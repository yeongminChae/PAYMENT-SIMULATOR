# 06. 가맹점 ID · 터미널 ID

- 상태: 결정
- 날짜: 2026-11-27
- 플랫폼 근거: ADR-0031, ADR-0047, ADR-0048 (Retail-Platform)
- 해소하는 차이: D15 (`00-플랫폼-차이.md`)

## 요점

- **가맹점 ID = 점포마다 하나, 터미널 ID = POS마다 하나.** 둘 다 카드사 · VAN이 발급한 번호다 (가정). 원본은 ERP 점포 · 기기 정보.
- **Payment가 posTrx의 점포 · POS로 직접 찾는다.** POS는 이 값을 보내지 않는다. 연결표는 Payment가 ERP에서 가져온다.
- **취소: 가맹점은 원승인과 같아야 하고, 터미널은 그 가맹점에 등록된 사용 중 터미널이면 된다.** 그래서 고객센터 POS에서 반품 취소가 된다 (ADR-0031). 현업에서 흔한 방식인지는 확인하지 않았다 (미확인).

## 1. 개념 (가정)

국내 오프라인 카드 결제에서 일반적으로 알려진 구조다. 실제 VAN 계약 문서로 확인하지 않았다.

- 가맹점 ID: 카드를 받는 사업자(가게)의 번호. 매출 정산 단위.
- 터미널 ID(TID): VAN이 결제 단말기마다 주는 번호. 어느 기계에서 결제했는지를 가리킨다.

## 2. 연결표

| ERP 원본 | Payment 사본 `MERCHANT_TERMINAL` |
|---|---|
| 점포 → 가맹점 ID | `STORE_CD` → `MERCHANT_ID` |
| 기기(POS) → 터미널 ID, 유형, 사용 여부 | `(STORE_CD, POS_NO)` → `TERMINAL_ID` · `DEVICE_TYPE` · `ACTIVE` |

- 대상 기기 유형: 판매 POS · 고객센터 POS. 운영 전용 POS(9999, ADR-0047)는 단말이 없어 터미널 ID가 없다.
- **동기화** (ADR-0048)
  - 하루 1회 전체를 받는다 (기본 03:00, 설정값).
  - 5분 운영 요청 수집 때 마지막 버전 이후 변경분을 함께 받는다. 새 기기 등록 · 사용 중지가 최대 5분 안에 반영된다.
  - ERP 연결이 안 되면 가진 사본으로 계속 처리한다. 30분 넘게 실패하면 알림 (05).

## 3. 승인

1. posTrx 앞부분에서 점포 · POS를 꺼낸다.
2. 연결표에서 찾는다. 없거나 사용 중지면 VAN 호출 없이 거부한다: `TERMINAL_NOT_REGISTERED` / `TERMINAL_INACTIVE`.
3. `PAYMENT_ATTEMPT`에 `MERCHANT_ID` · `TERMINAL_ID`를 저장한다. 그 승인 시점의 값이 고정된다. 이후 연결표가 바뀌어도 원승인 값은 그대로다.
4. VAN 승인 전문에 두 값을 싣는다.

## 4. 취소 · 망취소

| 거래 | 가맹점 | 터미널 |
|---|---|---|
| 고객 반품 취소 | 취소 POS의 가맹점 = **원승인 가맹점** | 취소 POS가 그 가맹점에 등록된 **사용 중 터미널** |
| 망취소 | 원승인과 같음 | 원승인과 같은 POS에서 오므로 같은 터미널 |
| 운영 취소 (04) | 원승인 값 사용 | 단말이 없으므로 **원승인 터미널 ID**로 VAN에 보냄 |

- 거부 코드: `MERCHANT_MISMATCH`(다른 점포의 결제 취소 시도), `TERMINAL_NOT_REGISTERED` · `TERMINAL_INACTIVE`.
- 카드 일치 검사(fingerprint)와 함께 쓴다. 카드가 맞아도 다른 점포에서는 취소할 수 없다.
- VAN 취소 전문에는 취소한 터미널 ID와 원승인 가맹점 ID를 싣는다.

## 5. VAN Simulator

- 승인 · 취소 · 망취소 전문에 `merchantId` · `terminalId`를 추가한다 (전문 버전 `protocolVersion` 2).
- VAN 원장에 저장하고, 취소 · 망취소는 원승인 가맹점과 같은지 확인한다. 다르면 거절 `MERCHANT_MISMATCH`.

## 6. 기존 데이터

- 이미 저장된 승인은 두 값이 없다(NULL). 그 승인의 취소는 가맹점 검사를 건너뛰고 경고 로그를 남긴다. 새 승인부터는 필수다.

## 7. 나중에 이어지는 것

- 매입 · 정산(07)은 가맹점 ID별로 묶는다.
- 카페 키오스크 · 소상공인(backlog)은 점포마다 사업자가 다를 수 있다. 가맹점 = 점포이므로 그대로 받아들이고, 가맹점 ID가 매출 귀속 키가 된다.

## 8. 구현 작업

1. `MERCHANT_TERMINAL` 테이블, ERP 동기화 (일 1회 전체, 5분 변경분)
2. 승인 입구 검사 · `PAYMENT_ATTEMPT` 컬럼 추가
3. 취소 · 망취소 · 운영 취소 검사
4. VAN 전문 v2 · VAN Simulator 저장 · 검사
5. 테스트: 미등록 · 사용 중지 터미널 승인 거부, 고객센터 POS 반품 취소 성공, 다른 점포 POS 취소 `MERCHANT_MISMATCH`, 운영 취소가 원승인 터미널로 나감, 연결표가 바뀌어도 원승인 값 유지
